# Android ARM64 regression checks

This standalone project builds five existing suites against real portable runtime
and native-core implementations. It does not configure the Windows renderer or
alter the application build.

From the repository root in PowerShell:

```powershell
$sdk = (Resolve-Path ../.tools/android-sdk).Path
& "$sdk/cmake/3.31.6/bin/cmake.exe" -S cmake/android_checks -B build/android-checks -G Ninja "-DCMAKE_TOOLCHAIN_FILE=$sdk/ndk/30.0.16248370/build/cmake/android.toolchain.cmake" -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-31 -DANDROID_STL=c++_shared -DCMAKE_BUILD_TYPE=Release "-DCMAKE_MAKE_PROGRAM=$sdk/cmake/3.31.6/bin/ninja.exe"
& "$sdk/cmake/3.31.6/bin/cmake.exe" --build build/android-checks -j2
python tools/run_android_checks.py --serial DEVICE_SERIAL
```

The runner accepts `--suite` (repeatable), `--timeout`, `--adb`, `--ndk`, and
`--build-dir`. It validates ARM64 ELF files before contacting adb, pushes only the
selected executables and libc++_shared.so, then runs them under device `timeout`.
Working directory, HOME and TMPDIR are within a unique run directory below
`/data/local/tmp/galaxy-checks`; cleanup removes only that run directory. Save
fixtures are generated by save_files_tests, never taken from application data.

Coverage:

- native_input_tests: button and script input, virtual pointer and motion, Wii
  Remote report decoding and settings-pad handling.
- mouse_projection_tests: exhaustive viewport samples, letterbox bars and invalid
  bounds against reference projection calculations.
- live_controls_engine_tests: controller families, keyboard, mouse, gyro pointer,
  recentering, focus, contexts and independent engine instances.
- save_files_tests: synthetic binary roundtrip, shorter replacement, rejected
  traversal names, insufficient buffer, missing files and deletion, through the
  real save_files.cpp and atomic_file.cpp implementations.
- math_tests: native math references, random matrices/vectors, aliasing, inverse
  edge cases and roundtrips; ARM64 compiles the NEON implementation.

Limits: these are native regressions, not Java touch gesture, gameplay, rendering
or performance validation. They do not exercise Android-specific event delivery.
The wider controls_tests and host_pointer_events_tests include Windows headers.
The legacy native/tests/run_tests.sh thread suite cannot be used unchanged:
thread_tests.cpp contains literal newlines in string literals, the script names
NebulaMemory.c which is absent, and current GameThreads.cpp needs an attached
NebulaHostServices implementation which the old test does not supply. No thread
stub or production-source modification is introduced here. Compiling the five
suites is not evidence that they passed on a device; use the runner for that.
